# AI Office — правка логики «Директор слышит, поручает, принимает работу»

Файл, который правим: **`ai_office.py`** (тот, что вы выложили на pastebin).
Стили, интерфейс, настройки, GitHub/Vercel, публикация — **не трогаем**.
Меняем только «мозг» директора: 5 правок + 1 большой готовый блок кода.

Готовый блок лежит рядом: **`director_logic_patch.py`** — его нужно
скопировать целиком в нужное место (ШАГ 4). Ничего в нём дописывать не надо.

---

## Почему сейчас «не слышит»

Сейчас маршрут такой:

```
ваше сообщение → detect_intent() (поиск ключевых слов по списку)
              → сразу исполнитель → его ответ вам как есть
```

Проблемы:

1. `detect_intent()` ищет **жёсткие фразы** («предложи темы», «5 тем»…).
   Скажете иначе («накидай пяток идей для блога») — попадёт в `general`,
   а там `choose_general_agent()` отдаст задачу Аналитику, который может
   написать одну статью.
2. **Никто не проверяет** результат. Что исполнитель вернул — то вы и получили.
3. Директор **не имеет собственной памяти**: он только ставит статус
   «думает» и всё. Память есть у чата (последние 10 сообщений) — и всё.

## Как будет

```
ваше сообщение
  → 👔 ceo_understand()    директор через нейросеть понимает: ЧТО, СКОЛЬКО, КОМУ + пишет ТЗ
  → исполнитель            получает ТЗ директора + ваш дословный запрос + критерии приёмки
  → 👔 ceo_review()        директор сверяет результат с вашим запросом
       ├ всё ок            → отдаёт вам
       ├ мелочи            → ceo_fix(): директор сам правит и отдаёт вам
       └ переделка         → возвращает исполнителю с замечаниями, потом снова проверяет
  → 👔 ceo_remember()      директор обновляет свою память по этому чату
```

Вы общаетесь только с директором. В «💭 Ход работы» под каждым ответом видно,
как директор понял запрос, кому поручил, и принял ли с первого раза.

## ШАГ 1. Подсказка директору (протокол `ceo`)

**Где:** блок `DEFAULT_PLAYBOOKS = {` , ключ `"ceo"` (примерно строка 120).

**Что делаем:** заменяем текст протокола директора.

Было:
```python
    "ceo": (
        "Ты директор AI Office. Веди связный диалог в рамках текущего чата. "
        "Сохраняй смысл предыдущих сообщений. Если пользователь уточняет, "
        "выбирает вариант или просит изменить готовый результат, продолжай "
        "текущую работу, а не начинай новую. Не подменяй просьбу пользователя "
        "своей заготовкой."
    ),
```

Стало:
```python
    "ceo": (
        "Ты директор AI Office. Пользователь общается только с тобой. "
        "Твоя работа: 1) точно понять, что просит пользователь — что именно, "
        "в каком количестве и в каком виде; 2) поставить чёткое задание нужному "
        "специалисту; 3) принять его работу, сверив с запросом пользователя; "
        "4) если результат не отвечает запросу — исправить или вернуть на доработку; "
        "5) помнить весь ход диалога и пожелания пользователя. "
        "«Предложи 5 тем» — это список из 5 тем, а не статья. «Напиши программу» — "
        "это код, а не текст о нём. Веди связный диалог: уточнение или выбор варианта — "
        "продолжение текущей работы, а не новая задача. Никогда не подменяй просьбу "
        "пользователя своей заготовкой."
    ),
```

> ⚠️ Если у вас уже есть `office_memory.json`, в нём сохранён **старый**
> протокол директора — он перекроет этот текст. После запуска откройте
> в левой панели «👔 Директор → Правка» и вставьте новый текст вручную
> (или удалите `office_memory.json` перед первым запуском — агенты создадутся заново).

## ШАГ 2. Память директора в каждом чате

**Где:** функция `default_session(sid)` (примерно строка 300).

**Что делаем:** добавляем одно поле `"ceo_memory"`.

Было (конец словаря):
```python
        "last_intent": "",
        "last_agent": "",
    }
```

Стало:
```python
        "last_intent": "",
        "last_agent": "",
        "ceo_memory": {"summary": "", "facts": []},
    }
```

**И там же, чуть ниже**, в `class Office.__init__`, в цикле
`for session in self.state["sessions"].values():` после строки
```python
            session.setdefault("last_agent", "")
```
добавляем:
```python
            session.setdefault("ceo_memory", {"summary": "", "facts": []})
```

Это чтобы **старые чаты**, сохранённые в `office_state.json`, тоже получили память.

**Зачем:** `summary` — краткое содержание всего диалога, `facts` — ваши
устойчивые пожелания («не использовать канцелярит», «выбрана тема №3»
и т.п.). Директор подмешивает это в каждый свой промпт, поэтому «помнит»
даже то, что уже вышло за пределы последних 10 сообщений.

## ШАГ 3. Подбор тем: число берёт директор

**Где:** функция `run_topic_research(user_text: str)` (раздел «ПОДБОР ТЕМ»).

**Что делаем:** даём функции принимать количество тем от директора.

Было:
```python
def run_topic_research(user_text: str) -> str:
    count = requested_options_count(user_text)
```

Стало:
```python
def run_topic_research(user_text: str, count: int | None = None) -> str:
    count = count or requested_options_count(user_text)
```

**Зачем:** раньше число вытаскивалось регуляркой (`\d+ тем`). Теперь его
понимает директор (в том числе «пять тем», «пяток идей», «ещё столько же»),
а регулярка остаётся запасным вариантом.

## ШАГ 4. Вставляем блок «Директор 2.0» (главная правка)

**Где:** сразу **после** функции `run_general_task(...)` и **перед** строкой

```python
# ============================================================
# ПЛАНИРОВЩИК ДИРЕКТОРА
# ============================================================

def process_message(text: str, attachments: list[dict] | None = None):
```

**Что делаем:**

1. Открываем `director_logic_patch.py`, копируем **всё содержимое начиная со строки**
   `# ДИРЕКТОР 2.0: ПОНИМАНИЕ ЗАПРОСА, ПАМЯТЬ, ПРИЁМКА РЕЗУЛЬТАТА` и до конца файла.
2. Вставляем в `ai_office.py` в указанное место.
3. **Удаляем старую** функцию `process_message(...)` целиком (от `def process_message`
   до строки `return run_general_task(text, attachments)` включительно) — в блоке
   уже есть её новая версия. Если оставить обе, Python возьмёт ту, что ниже,
   и будет путаница.

Что внутри блока (чтобы вы понимали, а не просто копировали):

| Функция | Роль директора | Что делает |
|---|---|---|
| `CEO_INTENTS` | справочник | какие типы задач бывают и кто их делает по умолчанию |
| `ceo_memory_text()` / `ceo_context_text()` | память | собирает память чата + «что на столе» (текущая статья, список тем, выбранная тема) |
| `heuristic_plan()` | запасной план | если нейросеть недоступна — работает старая логика по ключевым словам |
| **`ceo_understand()`** | **слушает** | нейросеть разбирает ваш запрос → JSON: `intent`, `agent`, `deliverable` («список из 5 тем про окна»), `count`, `brief` (ТЗ исполнителю), `acceptance` (критерии) |
| `build_agent_task()` | ставит задачу | склеивает ТЗ директора + ваш дословный текст + критерии приёмки |
| **`ceo_review()`** | **принимает работу** | сверяет результат с запросом → `ok / problems / can_fix` |
| `ceo_fix()` | правит сам | если недочёты мелкие — директор доводит результат и отдаёт вам |
| **`ceo_remember()`** | **помнит** | обновляет `summary` и `facts` в памяти чата после каждой задачи |
| `run_directed_task()` | общий сценарий | заменяет `run_general_task`: постановка → исполнитель → приёмка → (доработка 1 раз) → ответ |
| `ceo_final_check()` | приёмка готовых сценариев | для тем / статьи / правки статьи: если результат не по запросу и его можно поправить — директор правит и подменяет последнее сообщение в чате |
| `process_message()` | новый маршрутизатор | заменяет старый: сначала `ceo_understand`, потом нужный сценарий, потом приёмка и память |

Старую `run_general_task()` можно **не удалять** — она просто больше не вызывается.

## ШАГ 5. Ничего больше не трогаем

- `process_user_message()` — без изменений (она по-прежнему вызывает `process_message`).
- `detect_intent()`, `choose_general_agent()`, `requested_options_count()` —
  остаются как **запасной вариант**, когда API-ключ не задан или нейросеть
  вернула мусор (`heuristic_plan()` их использует).
- Публикация, предпросмотр, GitHub, Vercel, UI, стили — не менялись.

## Проверка после правок

1. Запустите приложение, убедитесь, что в верхней панели `API · подключена`.
2. Напишите: **«предложи 5 тем для публикации про окна»**
   → должен прийти список из 5 тем, в «💭 Ход работы»: *«Директор понял запрос как: список из 5 тем…»*.
3. Напишите: **«напиши мне программу — смета для расчёта монтажа окон»**
   → должен прийти код (Кодер), а не текст; директор в ходе работы отметил приёмку.
4. Напишите: **«сделай, чтобы смета считала ещё и откосы»**
   → директор должен понять, что это продолжение, и передать Кодеру с контекстом.
5. Напишите: **«о чём мы с тобой говорили?»**
   → директор отвечает сам (`agent: ceo`) на основе своей памяти.
6. Откройте `office_state.json` → у сессии появилось поле `ceo_memory`
   с `summary` и `facts`.

## Что стало дороже

На каждый запрос теперь **+2–3 коротких обращения к нейросети**
(понимание, приёмка, память). Это секунды и копейки на `gpt-4o-mini`,
но если хотите экономить — в `ceo_remember()` можно оставить только
запасную ветку без LLM (она всё равно пишет факт в память).

## Если что-то пошло не так

- **«Директор понял…» не появляется, всё как раньше** → вы не удалили старую
  `process_message` или вставили блок ниже неё. Должна остаться одна `process_message` — новая.
- **Ошибка `run_topic_research() got an unexpected keyword argument 'count'`** → пропущен ШАГ 3.
- **Ошибка `KeyError: 'ceo_memory'`** → пропущен `setdefault` из ШАГ 2.
- **Директор всё ещё пишет статью вместо списка** → проверьте, что в «👔 Директор → Правка»
  стоит новый протокол из ШАГ 1 (старый мог остаться в `office_memory.json`).
