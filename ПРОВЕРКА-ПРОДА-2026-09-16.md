# Проверка прода против разбора «H1 не подтверждён» — 2026-09-16

Разбор требовал пять замеров с реального `www.vektor-komforta.ru` вместо
локальной эмуляции. Требование справедливое: эмуляция ≠ прод. Замеры выполнены,
результаты — ниже. Коротко: **все пять пунктов на проде в порядке, H1 есть на
всех четырёх URL из разбора**. Данные разбора («H1 отсутствует, дальше дамп
бандла») — артефакт инструмента сбора, а не состояние прода. Доказательства —
по пунктам.

## 0. Метод (честно о том, как измеряли)

Прямой `curl` до прода из этой песочницы невозможен: egress-firewall режет TLS
до всех хостов, кроме allowlist (проверено: `registry.npmjs.org` и `github.com`
отвечают, `vektor-komforta.ru` — `SSL_ERROR_SYSCALL`, exit 35). Поэтому сырой
HTML прода получен двумя независимыми каналами, оба ходят за HTML **без
исполнения JS**:

1. **W3C Nu Html Checker** (`validator.w3.org/nu/?showsource=yes&doc=...`) —
   показывает исходник ответа сервера построчно. JS не исполняется: то, что
   видно в листинге, — ровно байты от Vercel.
2. **hackertarget `httpheaders`** — возвращает статус и заголовки ответа.

Контроль корректности каналов: W3C для `/okna` показал per-page description из
`api/page.ts` (строка 22), для `/` — description статического `index.html`,
для карточек — per-card description из `api/seo.js`. Значит, виден именно
серверный ответ соответствующих функций/статики, а не что-то иное.

Точные `curl`-команды для перепроверки с любой машины с интернетом — в §6.

## 2. Почему «данные сети» из разбора показывали пустоту

Разбор описывает картину «Title есть, H1 нет, дальше дамп inline-бандла».
Это в точности то, что видит инструмент **с лимитом размера ответа**:

- Собранный `dist/index.html` весит **1 293 212 байт** в текущей сборке
  и **1 292 943 байт** в задеплоенной (`b36c847`). Инлайн-бандл (JS + CSS)
  идёт в `<head>`, а `<div id="root">` начинается на байте **1 289 782 —
  99,73% файла**.
  *(Ранее в этом абзаце стояла цифра 1 049 591 байт — она не подтвердилась:
  `wc -c` по обеим версиям файла даёт значения выше. Порядок величины тот же,
  но точная цифра исправлена.)*
- Любой сборщик, режущий ответ (типичные лимиты 100 КБ–1 МБ) или сканирующий
  только `<head>`, увидит: корректный per-page Title → кусок бандла
  (`function(){const c=document.createElement("link")…`) → обрыв. H1, контент
  и ссылки физически окажутся за пределом выборки. Поле «H1 = текст Title» —
  fallback такого парсера.

Прямое подтверждение этого механизма получено в ходе проверки:
`hackertarget pagelinks` вернул **«no links found» даже для главной `/`** —
статического файла с 15 захардкоженными ссылками в сыром HTML. Инструмент
захлебнулся на мегабайтной странице. Данным из такого пайплайна нельзя
доверять ни по H1, ни по «пустому #root».

Вывод: утверждение разбора «H1 не подтверждён» говорит о способе сбора, а не
о проде. Полноразмерный сырой HTML (W3C, §1) подтверждает H1 на всех URL.

## 3. В чём разбор прав (принимается)

1. **Замеры против эмуляции ≠ замеры против прода.** Справедливо. Прошлый
   отчёт (`ОТВЕТ-СЕО-АНАЛИТИКУ-2026-09-16.md`, §4) фиксировал «310/310»
   локально и лишь предписывал прогнать `check:seo` против прода после
   деплоя. Теперь точечные замеры прода есть (этот документ). Полный прогон
   всех 310 URL против прода из этой песочницы невозможен технически
   (см. §0) — его нужно выполнить с машины с интернетом (§6).
2. **Заголовков в «данных сети» не было.** Верно, теперь заголовки сняты:
   `Cache-Control` есть везде, 404 честный.
3. **30-дневный план вне кода** (GSC/Вебмастер, переобход, ссылки, статьи) —
   принимается как есть, это работа вне репозитория. Единственное уточнение:
   техническая предпосылка плана («страницы рискуют не индексироваться»)
   не подтверждается — серверный HTML полный.

## 4. Откуда мог взяться разбор (гипотеза, не факт)

До деплоя текущего `main` карточки действительно отдавали пустой `#root`
(только мета-теги) — это зафиксировано в прошлом отчёте как «открытый
остаток». Если «данные сети» снимались до деплоя от 2026-09-16 и/или
усечённым сборщиком, картина «Title есть, H1 нет» для карточек объяснима.
Но отсутствие H1 на `/` (статика) и `/okna` (H1 там был и раньше) усечением
по размеру объясняется, а состоянием прода — нет. Точную причину по одной
цитате установить нельзя; важно, что **текущий прод проверен напрямую**.

## 5. Что исправлено этой проверкой (ветка, нужен деплой)

Проверка прода нашла **три реальных бага** (все видны в сыром HTML прода
прямо сейчас):

1. **Согласование рода: «Обычный/Мобильный/Инверторный сплит-система».**
   Тип в каталоге мужского рода, «сплит-система» — женского. Ошибка сидит
   в `meta description` всех 177 карточек (видно в прод-сниппетах: W3C,
   строка 22) и в серверном body. Исправлено картой `TYPE_FEMININE`
   (`Обычная/Инверторная/Мобильная/Полупромышленная/Промышленная`) в
   `api/seo.js` (сервер: description + body) и `src/pages/ConditionerPage.tsx`
   (клиентский `descText` после гидрации).
2. **Дубль `og:type` на карточках.** `api/seo.js` добавлял
   `<meta property="og:type" content="product">`, не заменяя `website` из
   оболочки. На проде два тега (W3C: строки 29 и 284), парсеры берут первый
   (`website`) — product-разметка для шеринга фактически не работает.
   Исправлено: теперь `og:type` оболочки **заменяется** на `product`.
   В `scripts/check-seo.mjs` добавлен регресс-чек «дубли og:type» (ошибка,
   не warning). Проверено на проде: в `api/seo.js` версии `b36c847`
   (то, что сейчас задеплоено) тег `product` **добавлялся** строкой 292
   при живом `website` из оболочки — отсюда два тега.
3. **Удвоение бренда: «Обычный сплит-система SHUFT SHUFT Berg SFTO».**
   Найден при повторной сверке с продом (см. §8). `api/seo.js` склеивал
   `${model.brand} ${model.name}`, а `name` в каталоге уже начинается
   с бренда — так во **всех 177** описаниях. Клиент
   (`src/pages/ConditionerPage.tsx`, строки 84–86) бренд дедуплицирует,
   сервер — нет, поэтому серверный сниппет расходился с клиентским.
   Исправлено: `safeFullName` по тому же правилу, что на клиенте.

Локальная проверка после правок: `npm run ci && npm run build` ✅,
`check:seo:local` — **310/310 OK, сайт-левел 6/6**, дублей `og:type` нет,
удвоений бренда 0, описания — «Обычная/Мобильная сплит-система», canonical
с `+`, честный 404. Изменённые файлы: `api/seo.js`,
`src/pages/ConditionerPage.tsx`, `scripts/check-seo.mjs`, пересобранный
`dist/index.html`.

**Регресс-чеки проверены отрицательным тестом** (иначе они ничего не стоят).
На намеренно испорченном `api/seo.js` (возврат к `${model.brand} ${safeName}`
и `${model.type}` вместо `${typeFem(…)}`) прогон дал ровно
**177 страниц с ошибками — по числу карточек кондиционеров**:
`удвоенный бренд` 177, `несогласованный род` 177, ложных срабатываний 0.
Первая версия чека ловила только соседние одинаковые слова и потому
пропускала 14 карточек с многословными брендами (Royal Thermo, AC ELECTRIC,
ONE AIR) — переписана на сравнение с брендом из JSON-LD страницы.
Первая версия чека рода давала 1 ложное срабатывание на статье
`/baza-znaniy/mobilnyy-konditsioner-ili-split-sistema` («Мобильный
кондиционер … сплит-система» — там род верный) — сужена до связки
«<тип> сплит-система».

Наблюдения без правок (решения за владельцем):
- В title/description **мобильных** карточек — «купить с установкой» /
  «Монтаж за 1 день», хотя мобильным монтаж не нужен (клиентский код это
  знает: «Монтаж не требуется — достаточно розетки»). Это вопрос шаблона,
  а не баг парсинга — не трогал.
- W3C ругается на косметику: `crossorigin` на `<style>` (singlefile-плагин),
  Tailwind `@property`, `itemprop` вне `itemscope` (теги из `api/seo.js`).
  На индексацию не влияет.
- `s-maxage=86400` из кода до клиента не доходит (Vercel отдаёт только
  `max-age=600`), но кэширование работает (`X-Vercel-Cache: HIT`).

## 6. Как перепроверить (5 команд разбора, буквально)

С любой машины с интернетом:

```bash
curl -s https://www.vektor-komforta.ru/okna | grep -o '<h1[^>]*>[^<]*' | head -1
# → <h1>Пластиковые окна и остекление балконов в Иркутске

curl -s https://www.vektor-komforta.ru/kondicionery/SHUFT-Berg-SFTO | grep -o '<h1[^>]*>[^<]*' | head -1
# → <h1>SHUFT Berg SFTO — купить с установкой в Иркутске

curl -sI https://www.vektor-komforta.ru/okna | grep -i cache-control
# → Cache-Control: public, max-age=600

curl -s "https://www.vektor-komforta.ru/kondicionery/Ballu-Twinkle-BPAC-09-DWB-Blue-+-UniPort" | grep -o '<link rel="canonical"[^>]*>'
# → <link rel="canonical" href="https://www.vektor-komforta.ru/kondicionery/Ballu-Twinkle-BPAC-09-DWB-Blue-+-UniPort" />

curl -sI https://www.vektor-komforta.ru/nesushchestvuyushchiy-url | head -1
# → HTTP/2 404 (код 404)
```

Важно: качайте ответ **целиком** (без `--max-filesize`, без `head -c`,
без чтения «первых N строк») — H1 лежит в самом конце мегабайтного HTML.

После мержа этой ветки в `main` и деплоя Vercel — дополнительно:

```bash
npm run check:seo -- https://www.vektor-komforta.ru > after.txt   # полный прогон 310 URL
curl -s https://www.vektor-komforta.ru/kondicionery/SHUFT-Berg-SFTO | grep -o '<meta name="description"[^>]*>' | grep -o 'Обычная сплит-система'
curl -s https://www.vektor-komforta.ru/kondicionery/SHUFT-Berg-SFTO | grep -c 'property="og:type"'  # → 1
```

**Что осталось неисправленным и почему.** W3C на каждой карточке отдаёт
4 HTML-ошибки, из них 3 — `The itemprop attribute was specified, but the
element is not a property of any item`: `<meta itemprop="name|price|
priceCurrency">` из `api/seo.js` лежат в `<head>`, а `itemscope` нигде не
объявлен. Это 531 ошибка валидации на 177 карточках. Не трогал сознательно:
лечится добавлением `itemscope itemtype="https://schema.org/Product"` на
`<html>`, но это меняет разметку на всех карточках сразу и может задеть
уже проиндексированную product-разметку — решение за владельцем.
На индексацию не влияет: цена и название продублированы в JSON-LD, который
валиден.

**Прямой `curl` с этой машины по-прежнему невозможен** — воспроизведено
заново: `curl: (35) OpenSSL SSL_connect: SSL_ERROR_SYSCALL in connection to
www.vektor-komforta.ru:443`. То же для `example.com` и `validator.w3.org`
из bash (HTTP=000), тогда как `api.github.com` отвечает 200 — то есть
закрыт именно выход наружу по произвольным хостам, а не весь интернет.
Поэтому §6 (пять команд буквально) остаётся в силе как способ перепроверки
с обычной машины.
