# 301-редиректы, честные 404 и «пропавший» noindex — 2026-09-13

Разбор по итогам проверки живого сайта и предыдущей сессии (PR #41 смержен, но последние
правки той сессии с серверным 301 в main **не попали** — коммит остался в закрытой ветке).
Здесь восстановлено и расширено.

---

## 1. Что реально происходит на проде (проверено 2026-09-13)

| Запрос | Фактический результат |
|---|---|
| `https://www.vektor-komforta.ru/burenie` | редирект на `/almaznoe-burenie` ✅ |
| `https://www.vektor-komforta.ru/standarty-montazha` | редирект на `/standarty` ✅ |
| `https://vektor-komforta.ru/burenie/` (apex + слэш) | цепочка → `https://www.vektor-komforta.ru/almaznoe-burenie` ✅ |
| `https://www.vektor-komforta.ru/almaznoe-burenie/` | слэш схлопывается → `/almaznoe-burenie` ✅ |
| `https://www.vektor-komforta.ru/api/page?path=/okna` | голый 404 (функция жива, путь берёт из `pathname`) |
| `https://www.vektor-komforta.ru/baza-znaniy/<несуществующий>` | честный 404 от `api/page.ts` ✅ |
| `https://www.vektor-komforta.ru/<любой мусор>` | **HTTP 200** + страница 404 → «мягкий 404» ❌ |

**Вывод по дублям:** редиректы на Vercel работают. «Дубли отдают 200» — это артефакт
инструмента проверки: он идёт за редиректом и показывает финальный статус (200) и финальный
Title. Яндекс.Вебмастер продолжает показывать старые URL в списке, пока не переползёт их —
это недели, а не минуты.

При этом нашлись **три настоящие проблемы**, которые и дают мусор в индексе.

---

## 2. Найденные проблемы

### P0 — `noindex, follow` на главных страницах (серверный HTML)

`api/page.ts` определял «есть ли фильтр в URL» так:

```ts
const hasFilterParams = url.search.length > 0;
```

Но Vercel сам добавляет в destination служебный параметр: rewrite
`/okna → /api/page?path=/okna`. То есть **у каждого rewrite-запроса query непустой**,
и условие срабатывало всегда. Результат: `/okna`, `/kondicionery` и все 34 гео-страницы
`/okna-*`, `/kondicionery-*` уходили краулеру с `<meta name="robots" content="noindex, follow">`
в серверном HTML.

Клиентский JS (`AC.tsx`, `useSeo`) эту мету снимает, поэтому в браузере всё выглядит чисто,
а вот краулер, читающий сырой HTML, видит запрет индексации. Отсюда «странные» диагнозы
в Вебмастере и склейки, которые живут своей жизнью.

### P1 — «мягкие 404» на любом мусорном адресе

Catch-all rewrite отдавал `index.html` со статусом **200** для всех неизвестных путей:
`/kakoy-to-musor`, `/favicon.ico`, `/wp-login.php`, probe-запросы ботов. React рисовал
страницу 404, но HTTP-статус был 200. Яндекс такие страницы считает мусором и может
трактовать как дубли.

### P2 — правила редиректов жили в четырёх местах и разъезжались

Списки дублировались руками в `vite.config.ts` (→ `vercel.json`), `public/_redirects`,
и их не было ни в `api/page.ts`, ни в SPA. Плюс алиас `/windows/:slug` рендерил тот же
контент, что `/okna/:slug`, со своим canonical — готовый дубль.

## 3. Что сделано

### 3.1 Единый источник правил — `src/constants/redirects.ts` (новый файл)

Все 301-правила теперь в одном модуле: точные (`LEGACY_REDIRECTS`) и групповые
(`LEGACY_PATTERN_REDIRECTS`, синтаксис Vercel/path-to-regexp). Там же `resolveLegacyRedirect()`,
который понимает оба вида правил, и `normalizePath()` (нижний регистр + без завершающего слеша,
идемпотентно — петлю редиректов создать не может).

Модуль намеренно без React: его импортирует edge-функция.

### 3.2 Уровень 1 — серверный 301 в `api/page.ts`

Хэндлер **до** поиска страницы проверяет правило и отдаёт честный 301:

```ts
const legacyTarget = resolveLegacyRedirect(path);
if (legacyTarget) {
  return new Response(null, { status: 301, headers: { Location: ..., "Cache-Control": "public, max-age=31536000" } });
}
```

`Location` абсолютный на боевом домене и относительный на preview-деплоях — превью не уводит на прод.

Там же:

- **починен P0**: `hasUserFilterParams()` игнорирует служебный `path`, поэтому `noindex, follow`
  ставится только на реальные фильтры (`?type=`, `?brand=`, `?page=`, `?q=`);
- **починен P1**: неизвестный путь → HTTP **404** + `noindex, follow`, но в оболочке SPA
  (React рисует оформленную страницу «Такой страницы нет», а не голую заглушку);
- файл-подобные адреса (`*.ico`, `*.php`, `*.png`, `/.env`) получают лёгкий 404 без подтягивания
  оболочки на 1.3 МБ — иначе каждый probe бота стоил бы инвоксации + внутреннего fetch;
- путь берётся из `pathname`, а при `pathname === "/api/page"` — из `?path=`
  (страховка на случай изменения поведения платформы);
- `decodeURIComponent` обёрнут в try/catch: кривой percent-encoding (`/okna%zz`) больше не роняет функцию в 500.

### 3.3 Уровень 2 — маршруты Vercel (`vite.config.ts` → `vercel.json`)

- `redirects` генерируются из `src/constants/redirects.ts` (17 правил, все `statusCode: 301`;
  схлопывание слеша переведено с 308 на 301 — единообразие);
- добавлены **страховочные rewrites**: старые адреса ведут в `api/page.ts`, чтобы серверный 301
  сработал, даже если слой редиректов хостинга не применился;
- catch-all переключён с `/index.html` на `/api/page?path=/$1` — это и есть фикс «мягких 404».
  Статические файлы Vercel отдаёт до rewrites, поэтому ассеты не задеты;
- `public/_redirects` (Netlify/Cloudflare) теперь генерируется из того же источника — 16 правил.

Итог: **17 редиректов и 149 маршрутов** в `vercel.json`.

### 3.4 Уровень 3 — клиентский `Navigate` (`src/components/LegacyRedirect.tsx` + `App.tsx`)

```tsx
<Route path="*" element={<LegacyRedirect fallback={<NotFound />} />} />
```

Если и хостинг, и серверный слой не сработали (локальный `npm run dev`, статический хостинг),
SPA уводит старый адрес на канонический сама. Правила — те же, из общего модуля.

Алиас `/windows/:slug` из роутов убран: канонический адрес карточки — `/okna/:slug`,
`WindowPage` от префикса пути не зависит, ссылок на алиас в коде нет.

### 3.5 `NotFound.tsx`

Ручная вставка `<meta name="robots">` заменена на `useSeo(..., { robots: "noindex, follow" })`:
мета больше не дублируется с серверной и корректно снимается при уходе со страницы
(прежний cleanup удалял только точное совпадение `content="noindex"`).

## 4. Как проверить после деплоя

```bash
# 1. Дубли обязаны отдавать 301 (важно: -I или --max-redirs 0, иначе клиент уйдёт за редиректом)
curl -sS -o /dev/null -D - --max-redirs 0 https://www.vektor-komforta.ru/burenie | grep -iE "^HTTP|^location"
# HTTP/2 301
# location: https://www.vektor-komforta.ru/almaznoe-burenie

curl -sS -o /dev/null -D - --max-redirs 0 https://www.vektor-komforta.ru/standarty-montazha | grep -iE "^HTTP|^location"
curl -sS -o /dev/null -D - --max-redirs 0 https://www.vektor-komforta.ru/windows/teploe-osteklenie-lodjii | grep -iE "^HTTP|^location"

# 2. Мусорный адрес — честный 404, а не 200
curl -sS -o /dev/null -w "%{http_code}\n" https://www.vektor-komforta.ru/kakoy-to-musor     # 404
curl -sS -o /dev/null -w "%{http_code}\n" https://www.vektor-komforta.ru/favicon.ico         # 404

# 3. ГЛАВНОЕ: на /okna и /kondicionery не должно быть noindex
curl -sS https://www.vektor-komforta.ru/okna | grep -o '<meta name="robots"[^>]*>'           # пусто
curl -sS https://www.vektor-komforta.ru/kondicionery | grep -o '<meta name="robots"[^>]*>'   # пусто
# а вот на фильтре — обязано быть:
curl -sS "https://www.vektor-komforta.ru/kondicionery?type=mobile" | grep -o '<meta name="robots"[^>]*>'
# <meta name="robots" content="noindex, follow" />

# 4. Серверный canonical на фильтре — чистый, без ?type=
curl -sS "https://www.vektor-komforta.ru/kondicionery?type=mobile" | grep -o '<link rel="canonical"[^>]*>'
```

Локально (без деплоя) поведение edge-функции проверяется стендом: сборка `api/page.ts`
через esbuild и прогон таблицы URL — статусы, `Location`, robots, canonical, покрытие всех
клиентских роутов, отсутствие петель. Прогнано: **342/342 проверки**, плюс jsdom-прогон SPA
(клиентские редиректы и страница 404) — всё зелёное.

## 5. Что смотреть в Яндекс.Вебмастере и когда

- **Индексирование → Страницы в поиске**: старые `/burenie` и `/standarty-montazha` будут
  висеть в списке, пока робот не переползёт их и не увидит 301. Ориентир — 2–4 недели.
- **Индексирование → Исключённые страницы**: после переполза они должны попасть в
  «Перенаправление (301/308)» — это и есть признак, что склейка сработала.
- **Канонические**: проверяется только из Вебмастера (снаружи `?type=` не увидеть —
  краулеру отдаётся чистый canonical + `noindex, follow`).
- Если после деплоя в Вебмастере появится всплеск «Запрещено к индексированию» по `/okna`
  и `/kondicionery` — это хвост P0-бага: страницы были с серверным `noindex`, теперь он снят,
  переиндексация займет несколько обходов робота.
