# Ответ SEO-аналитику — разбор плана «CSR → индексируемый HTML» — 2026-09-16

Отчёт аналитика (закрытие P0 через Puppeteer-пререндер) проверен против реального
кода репозитория. **Коротко: аналитик писал план вслепую, без доступа к репо и,
по-видимому, без проверки живого сайта** — его ключевая посылка «view-source =
`<div id="root"></div>` + `<script src="/assets/index-*.js">`» к этому проекту
не применима: билд одностраничный (`vite-plugin-singlefile`, никакого
`/assets/*.js`), а серверный HTML уже несколько итераций генерируют edge-функции
Vercel (`api/page.ts`, `api/seo.js`).

Итог этой сессии: **из всего списка аналитика реально открытыми были 3 пункта —
они закрыты в коде. Проверка «до/после» автоматизирована: 310/310 страниц
проходят 10 критериев аналитика + 6 сайт-левел проверок.**

## 2. Почему НЕ вариант А (Puppeteer-пререндер) и НЕ вариант Б (Vike/SSR)

Аналитик предлагал выбрать между пререндером Puppeteer'ом и миграцией на SSR-фреймворк.
Для этого стека оба варианта хуже статус-кво:

1. **Сайт уже имеет «вариант В» — серверный пререндер на edge-функциях.** Каждому
   запросу краулера Vercel отдаёт полный HTML (мета + h1 + текст + JSON-LD + ссылки),
   а пользователю — тот же HTML, который React дорисовывает. Это ровно тот результат,
   ради которого аналитик предлагал Puppeteer, только без headless-браузера в CI.
2. **Одностраничный билд делает Puppeteer-пререндер разрушительным.** `vite-plugin-singlefile`
   инлайнит весь бандл (~1,3 МБ) в каждый HTML. Пререндер 310 URL = **~400 МБ
   дублированного JS** в `dist/` против одного `index.html` сейчас. Плюс Chrome в CI
   ради контента, который edge-функция собирает за миллисекунды из константы.
3. **Шаг 5–6 плана аналитика (nginx, try_files) неприменим** — сайт на Vercel,
   маршрутизация в генерируемом `vercel.json`.
4. Вариант Б (Vike/Next) для 310 статичных страниц — согласен с аналитиком: оверкилл.
   Текущая схема даёт тот же индексируемый HTML без переписывания приложения.

**Важный нюанс архитектуры, который надо помнить** (проверено по документации Vercel):
статика приоритетнее rewrites. Поэтому `/` всегда отдаёт статический `dist/index.html`,
а не `api/page` — именно поэтому SEO-контент главной зашит прямо в `index.html`
(в `#root`; React при монтировании его заменяет). Все остальные пути не имеют
статических файлов и уходят в edge-функции.

## 3. Что изменено в коде

| Файл | Изменение |
|---|---|
| `api/seo.js` | Инжект серверного контента в `#root` карточек (h1, тип/бренд/цена, ссылки) + блок основных разделов + `Cache-Control`; canonical/og:url на `encodeURI` (склейка с sitemap) |
| `api/page.ts` | Навигационный блок «Разделы сайта» (14 ссылок, исключая текущую) в конец серверного body каждой страницы; `Cache-Control` на 200/404; расширен `bodyHtml` главной |
| `index.html` | Статический контент главной в `#root` расширен: 4 → 15 внутренних ссылок, добавлены блоки «Монтаж и сервис» и «О компании» |
| `src/pages/ConditionerPage.tsx`, `src/pages/WindowPage.tsx` | Клиентские canonical/share-URL: `encodeURIComponent` → `encodeURI` (идентично серверному canonical и sitemap) |
| `scripts/check-seo.mjs` | **Новый**: скрипт «до/после» из отчёта аналитика, адаптированный (см. §4) |
| `scripts/serve-local.mjs` | **Новый**: локальная эмуляция роутинга Vercel (redirects → статика → rewrites с вызовом `api/page.ts`, `api/seo.js`, `api/rss.ts`) — проверять SEO можно до деплоя |
| `package.json` | Скрипты `serve:local`, `check:seo`, `check:seo:local` |

Гарантии совместимости: React монтируется через `createRoot().render()`, который
полностью заменяет содержимое `#root` — статический контент пользователь видит
доли секунды до гидрации (и это же служит noscript-fallback). Схема уже работала
на проде с прошлых итераций (главная), здесь она лишь распространена на карточки.

## 4. Как проверять: before/after по аналитику, но без вслепую

Скрипт аналитика взят за основу и усилен под этот проект: список URL берётся из
`sitemap.xml` самого сайта; добавлены проверки canonical на самоссылку, регрессия
`noindex` (баг от 13.09, когда Vercel-параметр `?path=` принимался за фильтр),
честный 404 (включая несуществующие карточки), 301 со старых адресов, склейка
слешей, robots.txt и валидность sitemap.

```bash
# Локально, до деплоя (полная эмуляция прод-роутинга):
npm run build
npm run serve:local          # отдельный терминал: http://localhost:4173
npm run check:seo:local      # прогон всех 310 URL + сайт-левел проверки

# Результат этой сессии (локально):
#   Страниц: 310, OK: 310, с ошибками: 0
#   Мин. контент в #root: 387 симв. | мин. внутренних ссылок: 9
#   Сайт-левел: 6/6 OK (404, 301, слеши, robots, sitemap)

# На проде — «до» (пока деплой не сделан) и «после»:
npm run check:seo -- https://www.vektor-komforta.ru > before.txt   # сейчас
git push … деплой …
npm run check:seo -- https://www.vektor-komforta.ru > after.txt    # после
diff before.txt after.txt
```

Быстрый прогон: `node scripts/check-seo.mjs https://www.vektor-komforta.ru --max=30 --quiet`.

Ожидаемая дельта на проде после деплоя (страницы, которых касались правки):

| Метрика | До (прод) | После |
|---|---|---|
| Контент в `#root` карточек | 0 симв. | ≥ 387 симв. |
| Внутренних ссылок: услуги/гео/статьи | 0–3 | 14 |
| Внутренних ссылок: карточки | 0 | 9 |
| Внутренних ссылок: главная | 4 | 15 |
| `Cache-Control` на edge-HTML | нет | `max-age=600, s-maxage=86400` |
| canonical на карточках с «+» | `%2B` (расходится с sitemap) | `+` (совпадает) |

После деплоя: переобход в Яндекс.Вебмастере («Удалить URL» + «Переобойти» для
карточек) и Google Search Console (Проверка URL → Запросить индексирование).

1. `vite.config.ts` и `vercel.json` — по ним за минуту видно, что CSR-пустышки нет.
2. Живой сайт: `curl -s https://www.vektor-komforta.ru/okna | grep h1` — серверный
   контент был виден и до этой сессии.
3. Документы в корне репо (`SEO-AUDIT.md`, `SEO-AUDIT-ROUND2-2026-08-15.md`,
   `РЕДИРЕКТЫ-301-И-ЧЕСТНЫЕ-404-2026-09-13.md`) — история того, что уже закрыто.

Реальные ограничители роста сайта — не индексируемость (она теперь в порядке), а
то, что честно описано в аудите №2: ссылочная масса ≈ 0, молодой домен,
поведенческие факторы. Это работа вне кода.
